# 빌드와 입력 안내

## 전체 검증

저장소 루트에서 Python 3.10 이상과 C11 컴파일러로 실행한다. 외부 Python 패키지는 필요 없다.

```bash
python tools/verify.py --cc gcc
python tools/verify.py --cc "zig cc"
```

컴파일러 경로에 공백이 있으면 `--cc` 값 안에서 실행 파일 경로를 따옴표로 감싼다. 출력은 `build/`에 생성한다. 프로그램마다 독립된 `main`이 있으므로 모든 C 파일을 한 번에 링크하지 않는다. `week12/assignment01_guess.c`만 `week12/guess.c`와 함께 링크한다.

기록을 새 실행 결과로 갱신하려면 `--report`를 붙인다. 이 옵션은 `results/verification.json`과 주차별 `results/sample_run.txt`를 덮어쓴다. 일반 검증은 저장된 기록을 수정하지 않는다.

## Windows와 Visual Studio

Visual Studio의 C++ 데스크톱 개발 도구가 설치되어 있다면 빈 콘솔 프로젝트를 만들고 원하는 `.c` 파일을 추가한다. 확장자는 `.c`로 유지한다. 같은 폴더의 `.h` 파일도 함께 보관한다. MSVC가 `scanf`에 C4996 경고를 표시하면 해당 프로젝트의 전처리기 정의에 `_CRT_SECURE_NO_WARNINGS`를 추가할 수 있다. 이 저장소의 실측 빌드 결과는 Visual Studio가 아니라 Zig C 컴파일러에서 얻었다.

명령줄 예제의 `./exercise`는 Windows에서는 `.\exercise.exe`로 실행한다. 실행 파일은 저장소에 포함하지 않는다.

## 입력 계약

주차별 README의 순서에 따라 공백 또는 줄바꿈으로 구분한 값을 입력한다. 프로그램은 검사 자동화를 위해 입력 프롬프트 없이 결과를 출력한다. 정수 입력은 **32비트 int로 표현 가능한 숫자**를 전제로 한다. 숫자가 아닌 입력이나 프로그램별 범위 밖의 값은 대부분 종료 코드 1로 거부한다. 범위를 넘는 정수 문자열을 안전하게 파싱하는 범용 입력 라이브러리는 이 기초 `scanf` 실습의 범위가 아니다.

문자 예제는 ASCII 영문자 기준이다. 수치 예제의 추가 범위 제한, 종료 값, 배열 초기값은 각 README에 명시했다. 고정 예제는 표준입력이 없다. 난수 게임은 1~100 값을 반복 입력하고, 구구단·함수 성적 처리는 계속 여부 1 또는 0을 입력한다. 시간 함수는 0 0 0으로 종료한다.

실수 출력은 표시 자릿수로 반올림되지만 학점 판정에는 반올림 전 평균을 쓴다. 난수 값은 실행마다 달라질 수 있어 저장된 로그와 숫자 순서가 같을 필요는 없다.
